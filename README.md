# Butter & Bloom Pâtisserie — QR Ordering System

A QR-code table-ordering web app for a pastry shop. Customers scan a QR at their table, browse the menu, review a cart, send orders to the kitchen, and check an itemized bill. The kitchen sees new orders live.

**Stack:** Next.js (App Router, JavaScript) · Supabase (Postgres + Realtime) · Vercel · GitHub

---

## Pages

| Route | Who | Purpose |
|---|---|---|
| `/` | Anyone | Shop name + links to staff pages |
| `/generate-qr` | Front staff | Open a table → get a QR code. Can force-close a stuck table |
| `/order/[token]` | Customer | Browse menu by category, add items |
| `/cart/[token]` | Customer | Review cart, change quantities, send order to kitchen |
| `/bill/[token]` | Customer | Itemized bill of everything ordered, request bill / close table |
| `/kitchen` | Kitchen staff | Live order board (start preparing / mark served) |

`[token]` is a random UUID generated **per table session**, not the table number. Every time a table is opened, it gets a new token, so an old QR code stops working once the table is closed.

## 2. Supabase setup

### 2.1 Create the project
1. Go to [supabase.com](https://supabase.com) → **New project**.
2. Name it (e.g. `butter-and-bloom`), set a database password, pick the region closest to you (e.g. Singapore).
3. Wait 1–2 minutes for it to finish provisioning.

### 2.2 Create the tables
Open **SQL Editor → New query**, paste the whole block below, and click **Run**.

```sql
-- One row per table visit (from "open table" until the bill is requested)
create table sessions (
  id bigint generated by default as identity primary key,
  table_number int not null,
  token uuid not null default gen_random_uuid() unique,  -- used in customer URLs
  status text not null default 'open' check (status in ('open', 'closed')),
  total_amount numeric(10,2),                            -- filled in when closed
  created_at timestamptz not null default now(),
  closed_at timestamptz
);

-- A table can have only ONE open session at a time
create unique index one_open_session_per_table
  on sessions (table_number) where status = 'open';

create table menu_categories (
  id bigint generated by default as identity primary key,
  name text not null,
  sort_order int not null default 0
);

create table menu_items (
  id bigint generated by default as identity primary key,
  category_id bigint not null references menu_categories(id),
  name text not null,
  price numeric(10,2) not null check (price >= 0),
  is_available boolean not null default true
);

-- One row per "send order" press. items is a price SNAPSHOT:
-- [{"item_id": 1, "name": "Velvet Moon Slice", "price": 120, "quantity": 2}]
create table orders (
  id bigint generated by default as identity primary key,
  session_id bigint not null references sessions(id),
  table_number int not null,
  items jsonb not null,
  status text not null default 'received'
    check (status in ('received', 'preparing', 'served')),
  created_at timestamptz not null default now()
);

-- Row Level Security: open access (fine for a class project only)
alter table sessions enable row level security;
alter table menu_categories enable row level security;
alter table menu_items enable row level security;
alter table orders enable row level security;

create policy "allow all - sessions" on sessions for all using (true) with check (true);
create policy "allow all - menu_categories" on menu_categories for all using (true) with check (true);
create policy "allow all - menu_items" on menu_items for all using (true) with check (true);
create policy "allow all - orders" on orders for all using (true) with check (true);
```

> ⚠️ `using (true)` lets anyone read and write everything. Acceptable for a class demo, not for production.

### 2.4 Enable Realtime on `orders`
The kitchen screen needs this to update without refreshing. Run in SQL Editor:

```sql
alter publication supabase_realtime add table orders;
```

(Or via the dashboard: **Database → Publications → `supabase_realtime`** → toggle `orders` on. Note: "Replication" is a different feature — you want **Publications**.)

### 2.5 Get your API keys
1. **Project Settings** (gear icon) → **API** (may be labeled *API Keys* / *Data API*).
2. Copy two values:
   - **Project URL** — looks like `https://xxxx.supabase.co`
   - **anon public key** — long string starting with `eyJ...`
3. 🚫 **Never use the `service_role` / `secret` key.** It bypasses all security and must not appear in this project.

## 3. Environment variables

The app reads exactly two variables:

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL from step 2.5 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key from step 2.5 |

**Local development:** copy `.env.example` to `.env.local` and fill in the values. `.env.local` is git-ignored — never commit it.

```bash
cp .env.example .env.local
```

**Vercel:** set the same two variables in the project settings (see step 5).

## 5. Deploy

1. Push the project to a GitHub repository (e.g. `butter-and-bloom-order`).
2. Go to [vercel.com](https://vercel.com) → **Add New → Project** → import the repo.
3. Before clicking Deploy, open **Environment Variables** and add both variables from step 3.
4. Click **Deploy**. You'll get a URL like `https://butter-and-bloom-order.vercel.app`.
5. Every future push to GitHub redeploys automatically. If you add or change env vars afterwards, **Redeploy** manually.

## 6. Test checklist

Open three tabs: `/generate-qr`, `/kitchen`, and (later) the customer link.

1. **Open a table:** `/generate-qr` → table `5` → *Open table*. A QR, a link like `/order/<uuid>`, and a copy button appear.
2. **Customer:** open that link. Menu tabs appear; add 2–3 items. The floating bar shows item count + total.
3. **Cart:** open the cart. Change a quantity, remove one item, confirm the subtotal updates. Press *Send to kitchen*.
4. **Kitchen:** the order appears **without refreshing**. Press *Start preparing*, then *Served* — the card disappears.
5. **Bill:** on the customer side open the bill. Items are aggregated with line totals and a correct grand total.
6. **Stuck table:** in `/generate-qr` enter table `5` again. A warning appears with *Close old order*. Confirm the dialog (shows minutes open, order count, running total). The form returns with values kept; press *Open table* — a **new** URL/token is issued.
7. **Old QR dead:** the previous customer link now shows the "thanks / table closed" screen.
8. **Request bill:** on a fresh session, press *Request bill* on the bill page → confirm → thank-you screen with the total.
9. **Bad link:** visit `/order/not-a-real-token` → "Invalid link" message (no crash).

## 7. Troubleshooting

| Problem | Likely cause | Fix |
|---|---|---|
| White page / error after deploy | Missing or wrong env vars | Check Vercel → Settings → Environment Variables, then Redeploy |
| "permission denied" / empty data | RLS policies not created | Re-run the policy statements in step 2.2 |
| Kitchen doesn't update live | Realtime not enabled on `orders` | Run the SQL in step 2.4 |
| "Invalid link" right after opening a table | Route param not unwrapped | In Next.js 15+, use `const { token } = use(params)` (`import { use } from "react"`) |
| Can't open a table ("duplicate key") | Table already has an open session | Use *Close old order* on `/generate-qr` |
| QR image missing | URL not encoded | Wrap the URL in `encodeURIComponent()` in the QR image src |
| Vercel build fails | Wrong file path/name | Check the build log; paths must match `app/order/[token]/page.js` exactly (square brackets) |

## 8. Known limitations (MVP)

- No real payment — "Request bill" just closes the session and shows the total; customers pay at the counter.
- No login: `/generate-qr` and `/kitchen` are open to anyone who knows the URL.
- Open RLS policies: anyone with the anon key can read every table. Fine for a class project only.
- Cart is stored in the browser (`localStorage`), so it doesn't sync across devices.
- Menu is edited in Supabase Table Editor (no admin page).
